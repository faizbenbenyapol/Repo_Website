## เพิ่ม

- ชุดทดสอบอัตโนมัติด้วย axe-core ตรวจ WCAG 2.1 AA (`wcag2a`/`wcag2aa`/`wcag21a`/`wcag21aa`) ทุกหน้าหลัก
  ทั้งธีมสว่างและธีมมืด — หน้าแรก หน้าเข้าสู่ระบบ หน้าสมัครสมาชิก หน้าประวัติเวอร์ชัน หน้าแผนที่โค้ด
  หน้าสุขภาพโค้ด และหน้าถาม–ตอบ รวม 11 เทสต์
- ชุดทดสอบอัตโนมัติตรวจว่าไม่มีหน้าไหนล้นแนวนอนที่ความกว้างมือถือ (375px) ครอบคลุมหน้าหลักชุดเดียวกัน

## แก้

- สีตัวหนังสือรอง (`--color-muted`, `--color-faint`) และสีทองแดง (`--color-brass`) เข้มไม่พอจนคอนทราสต์
  กับพื้นหลังต่ำกว่า 4.5:1 จริงตอนเรนเดอร์ — ค่าที่คำนวณตามสูตรทฤษฎีผ่าน แต่การเรนเดอร์ตัวอักษรเล็กจริง
  ในเบราว์เซอร์มี anti-aliasing ที่ลดคอนทราสต์ลงจากค่าทฤษฎีอีกชั้นหนึ่ง จึงต้องเผื่อขอบเพิ่มทั้งสองธีม
- ปุ่มหลัก (bg-accent + ตัวหนังสือขาว) ในธีมมืดอ่านแทบไม่ออก (วัดได้ 2.29:1) เพราะสีเน้นของธีมมืดต้อง
  สว่างพอให้ตัวมันเองอ่านออกบนพื้นมืด แต่พาสเทลสว่างขนาดนั้นใส่ตัวหนังสือขาวทับไม่ผ่านเกณฑ์ — เพิ่มโทเค็น
  `--color-on-accent` แยกต่างหาก (ขาวในธีมสว่าง เข้มในธีมมืด) ให้ทุกปุ่มสีเน้นใช้แทน `text-white` เดิม
- แถบหัวเว็บ (โลโก้ + เมนู + ชิปเซสชัน) ล้นออกนอกจอที่ความกว้างมือถือ 375px (ยาวเกิน 21px) — ให้เมนูตัด
  บรรทัดได้ตามพื้นที่ที่เหลือ และซ่อนลิงก์ "ต้นทางแนวคิด" ซึ่งสำคัญน้อยสุดไว้บนจอกว้างขึ้นเท่านั้น
- axe รายงานคอนทราสต์ผิดพลาดที่หน้าถาม–ตอบเป็นบางครั้ง — สาเหตุคือสแกนไปกลางอนิเมชันจางเข้า (`.rise`)
  ขณะองค์ประกอบยังโปร่งแสงไม่เต็มที่ ไม่ใช่ปัญหาสีจริง แก้ที่ชุดทดสอบให้ปิดอนิเมชันก่อนสแกนเสมอ
- ยอดรวม `engines.treeSitter`/`engines.pattern` ของผลวิเคราะห์รายงานเป็น 0 เมื่อทุกไฟล์ในรอบนั้นไม่มี
  การเปลี่ยนแปลงเลยและใช้ผลจากรอบก่อนซ้ำทั้งหมด (การวิเคราะห์ซ้ำแบบ incremental ของ v0.7.0) ทั้งที่ทุกไฟล์
  ผ่านการพาร์สจริงมาก่อนแล้ว — ตอนนี้เก็บเครื่องมือที่พาร์สแต่ละไฟล์ไว้รายไฟล์ (คอลัมน์ `files.engine`)
  เพื่อให้รอบที่ใช้ผลเดิมซ้ำยังรวมยอดจากไฟล์ที่ข้ามไปได้ถูกต้อง

## ปรับ

- ปุ่มและลิงก์ที่มีสถานะโฟกัสหรือ hover ผ่านการตรวจ axe ครบทุกหน้า ไม่ใช่แค่ไม่มีปัญหาระดับ critical
  เหมือนเกณฑ์ผ่านขั้นต่ำของ PLAN.md — เป้าคือไม่มีปัญหาการเข้าถึงเลยสักข้อในทุกหน้าที่ทดสอบ

## หมายเหตุอัปเกรด

- เกณฑ์ "60fps" ของ PLAN.md ตรวจแบบอ่านโค้ดเป็นหลัก ไม่ได้วัดเฟรมจริงด้วยเครื่องมือโปรไฟล์: อนิเมชันที่มี
  อยู่ทั้งหมดในเว็บ (`.rise`, `animate-pulse`, การเปลี่ยนสี/ทรานส์ฟอร์มตอน hover) เป็น CSS ล้วนและแตะแค่
  `opacity`/`transform` ซึ่งเบราว์เซอร์รันบน compositor แยกจาก main thread ได้โดยไม่ชนเฟรมอยู่แล้ว
  ไม่มี `requestAnimationFrame` หรือลูปแอนิเมชันที่เขียนเอง กราฟความสัมพันธ์ที่วาดด้วย sigma.js/WebGL
  ยังไม่ได้ถูกวัดประสิทธิภาพกับ repo ขนาดใหญ่มากเป็นพิเศษโดยเฉพาะ
- คอลัมน์ `files.engine` ใหม่เป็น `null` สำหรับผลวิเคราะห์เก่าที่มีอยู่ก่อนอัปเกรดรุ่นนี้ — รอบวิเคราะห์ซ้ำ
  ของ repo เหล่านั้นจะยังไม่รวมยอด engines ของไฟล์ที่ใช้ผลเดิมซ้ำจนกว่าจะมีการวิเคราะห์แบบเต็มรูปแบบอีกครั้ง
  ไม่กระทบข้อมูลอื่นใด เป็นแค่ตัวเลขสรุปที่จะถูกต้องเองเมื่อวิเคราะห์ใหม่
