## เพิ่ม

- โครงสร้าง monorepo ด้วย pnpm workspaces แยกเป็น `@repolens/web`, `@repolens/api` และ `@repolens/shared`
- Fastify API พร้อมเส้นทาง `/api/health`, `/api/version`, `/api/versions`, `/api/versions/:version` และ `/api/session`
- หน้าเว็บ Next.js 15: หน้าแรกที่อธิบายสองระดับการใช้งาน และหน้า `/versions` ที่อ่านบันทึกรุ่นย้อนหลังได้ทุกรุ่น
- ป้ายบอกรุ่นมุมล่างทุกหน้า แสดงเวอร์ชัน วันที่ build และ git sha ที่ฝังตอนสร้างอิมเมจ
- ระบบบันทึกรุ่นภาษาไทย: หนึ่งไฟล์ต่อรุ่นใน `docs/changelog/` ประกอบเป็น `CHANGELOG.md` อัตโนมัติ
  และเป็นแหล่งข้อมูลเดียวกับที่หน้าเว็บอ่าน
- ตัวตรวจบันทึกรุ่นที่ทำให้ CI ตกถ้าเวอร์ชันในโค้ดกับบันทึกรุ่นไม่ตรงกัน หรือ `CHANGELOG.md` ไม่ถูกประกอบใหม่
- ตารางระดับการใช้งานสองระดับ (ผู้เยี่ยมชม / สมาชิกที่ใส่ API key ของตัวเอง) เป็นแหล่งความจริงเดียวใน `@repolens/shared`
- สภาพแวดล้อม Docker ครบวงจร: `compose.yaml` สำหรับพัฒนา, `compose.test.yaml` สำหรับทดสอบ,
  `compose.prod.yaml` พร้อม Caddy สำหรับขึ้นจริง และ `Makefile` เป็นทางเข้าเดียวของทุกคำสั่ง
- GitHub Actions ที่รันชุดทดสอบเดียวกับที่นักพัฒนารันในเครื่อง แล้ว build อิมเมจขึ้น registry เมื่อติดแท็กรุ่น
- ระบบสีและตัวอักษรของหน้าเว็บ รองรับทั้งธีมสว่างและมืด พร้อมเคารพการตั้งค่าลดการเคลื่อนไหวของเครื่องผู้ใช้

## แก้

- คำขอ `/api/*` ที่ผ่านหน้าเว็บไปไม่ถึง API เมื่อรันจากอิมเมจ production เพราะ `rewrites` ของ Next
  ถูกคำนวณตอน build ทำให้ค่า `API_ORIGIN` ถูกฝังตายไปกับอิมเมจ — เปลี่ยนไปใช้ตัวส่งต่อที่อ่านค่าตอนรันจริง

## หมายเหตุอัปเกรด

- รุ่นนี้ยังไม่วิเคราะห์โค้ดจริง การรับลิงก์ repo และไปป์ไลน์วิเคราะห์เริ่มที่ v0.2.0
- ระบบล็อกอินและช่องใส่ API key จะลงจริงพร้อมชั้นความเข้าใจในรุ่น v0.5.0
  รุ่นนี้มีเพียงตารางระดับการใช้งานและเส้นทาง `/api/session` ที่รายงานว่าตอนนี้อยู่ระดับผู้เยี่ยมชม
