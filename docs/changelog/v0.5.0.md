## เพิ่ม

- ระบบสมาชิกด้วยบัญชีในระบบเอง — สมัคร เข้าสู่ระบบ และออกจากระบบ
  รหัสผ่านแฮชด้วย scrypt พร้อมเกลือของตัวเอง และ session เป็นโทเค็นสุ่มในคุกกี้ที่สคริปต์อ่านไม่ได้
  โดยฐานข้อมูลเก็บไว้แค่ค่าที่ย่อแล้ว ถ้าฐานข้อมูลหลุดก็เอาไปสวมรอยไม่ได้
- ช่องใส่ API key ของ Claude ที่หน้า `/account` — ตรวจกับ Anthropic ให้ก่อนรับเก็บ
  จึงรู้ตั้งแต่ตอนใส่ว่าพิมพ์ผิดหรือเปล่า แทนที่จะไปรู้ตอนสั่งสรุปแล้วรอฟรีไปสองนาที
- กุญแจของสมาชิกอยู่ในหน่วยความจำเท่านั้น เข้ารหัสด้วย AES-256-GCM และหมดอายุเองใน 12 ชั่วโมง
  ไม่เคยถูกเขียนลงฐานข้อมูล ไม่เคยลง log และไม่เคยถูกส่งกลับไปหน้าเว็บ — สิ่งที่หน้าเว็บรู้ได้มากที่สุดคือสี่ตัวท้าย
- ชั้นความเข้าใจแบบสามชั้น — สรุปรายไฟล์ รวมเป็นภาพของแต่ละโมดูล แล้วสรุปภาพรวมทั้ง repo
  ตอบให้ได้ว่าโปรเจกต์นี้ทำอะไร สร้างด้วยอะไร เริ่มอ่านจากไฟล์ไหน รันอย่างไร และมีอะไรควรระวัง
- ทุกประโยคของคำอธิบายต้องชี้บรรทัดจริงในโค้ดได้ ข้อที่ชี้ไม่ได้ถูกตัดทิ้งก่อนถึงหน้าจอ
  ไม่ใช่แสดงแบบไม่มีที่มา เพราะคำอธิบายที่ตรวจย้อนกลับไม่ได้และฟังดูน่าเชื่อ อันตรายกว่าการไม่มีคำอธิบายเลย
- ไฟล์ทุกไฟล์มีคำอธิบายเสมอ ไฟล์ที่เกินเพดานการเรียกโมเดลหรืออ่านเนื้อหาไม่ได้
  จะได้คำอธิบายที่ระบบเขียนเองจากโครงสร้างที่วัดได้ และติดป้ายบอกไว้ว่ามาจากไหน
- แผงรายละเอียดไฟล์ในแผนที่โค้ดแสดงคำอธิบายของไฟล์นั้น พร้อมป้ายอ้างอิงที่คลิกกระโดดต่อได้
- หน้ารายงานเพิ่มส่วนสรุปภาษาไทยของทั้ง repo และคำอธิบายรายโมดูล
- ปุ่มสั่งสรุปพร้อมแถบความคืบหน้าที่เดินตามขั้นจริงผ่าน SSE และบอกจำนวนไฟล์ที่สรุปไปแล้ว
- คิวงานที่สองแยกจากคิววิเคราะห์ คนที่แค่อยากดูกราฟจึงไม่ต้องรอคิวของคนที่สั่งสรุปทั้ง repo
- แพ็กเกจ `@repolens/ai` — ตัวเรียก Claude API ที่เขียนบน fetch เอง ไม่มี dependency ภายนอกเพิ่ม
  พร้อมตัวแกะ JSON ที่ทนคำตอบเพี้ยน และตัวตรวจอ้างอิงที่ตัดข้อที่ยืนยันไม่ได้ออก
- เพดานจำนวนไฟล์ต่อการสรุปหนึ่งรอบ และเพดานจำนวนครั้งที่สั่งสรุปได้ต่อชั่วโมง
  เพราะค่าเรียกใช้โมเดลตกกับกุญแจของผู้ใช้ทุกบาท จำนวนครั้งจึงต้องคาดเดาได้
- นับโทเค็นที่ใช้ไปทั้งงานแล้วแสดงให้เจ้าของกุญแจเห็นว่ารอบนี้จ่ายไปเท่าไร
- `git clone` รับหมายเลขคอมมิตได้แล้ว งานสรุปจึงกลับไปอ่านโค้ดของคอมมิตเดียวกับที่วิเคราะห์ไว้ได้

## แก้

- ตารางฟีเจอร์ยังบอกว่าคะแนนสุขภาพ รัศมีผลกระทบ และการส่งออก JSON เป็นของที่ยังไม่มี
  ทั้งที่ปล่อยไปตั้งแต่ v0.4.0 — หน้าแรกจึงโฆษณาน้อยกว่าที่ทำได้จริงมาตลอดหนึ่งรุ่น
- ตัวส่งต่อคำขอของหน้าเว็บรวมคุกกี้หลายใบเป็นค่าเดียว ซึ่งเบราว์เซอร์อ่านไม่ออก
  ตอนนี้ส่งต่อทีละใบตามที่ควรเป็น
- ข้อความบนหน้าแรกยังบอกว่ารุ่นปัจจุบันคือ v0.2.0 ทั้งที่ผ่านมาสองรุ่นแล้ว
- เพดานการสั่งวิเคราะห์หักโควตาให้คำขอที่จบลงด้วยการคืนผลที่แคชไว้ด้วย
  ทั้งที่คำขอแบบนั้นไม่ได้ทำให้เครื่องโคลนอะไรเลย — เพดานนี้มีไว้กันการโคลน ไม่ใช่กันการอ่านผลเดิม
- migration ที่ถูกเรียกพร้อมกันจากหลายกระบวนการชนกันเองตอนฐานข้อมูลยังว่าง
  เพราะล็อกถูกจับคนละการเชื่อมต่อกับตัวที่รัน migration จริง ล็อกนั้นจึงไม่ได้กันอะไรเลยมาตั้งแต่ v0.2.0
  บนเซิร์ฟเวอร์จริงคือกรณีที่ API กับ worker ขึ้นพร้อมกันครั้งแรก แล้วตัวที่แพ้เปิดไม่ขึ้น

## ปรับ

- Redis ทำงานในหน่วยความจำล้วนทั้งสามสภาพแวดล้อม เพื่อให้คำว่า "กุญแจไม่ลงดิสก์" เป็นจริง
  ไม่ใช่แค่ความตั้งใจ — แลกกับการที่งานค้างคิวจะหายเมื่อรีสตาร์ต ซึ่งสั่งใหม่ได้
- คุกกี้และหัวข้อ `set-cookie` ถูกกลบใน log ด้วย เพราะโทเค็น session สวมรอยเป็นเจ้าของบัญชีได้ทันที
- แยกตัวจำกัดอัตราออกมาเป็นโมดูลของตัวเอง เพราะตอนนี้มีสามที่ที่ต้องใช้กติกาเดียวกัน
- แยก worker เป็นไฟล์ต่อชนิดงาน จากเดิมที่รวมอยู่ไฟล์เดียว

## หมายเหตุอัปเกรด

- ต้องตั้ง `SESSION_SECRET` ก่อนเปิดบริการ สร้างด้วย `openssl rand -hex 32`
  API จะไม่ยอมเปิดบนเซิร์ฟเวอร์จริงถ้าไม่มีค่านี้ และถ้าเปลี่ยนค่า กุญแจที่ผู้ใช้ผูกไว้จะถอดไม่ออกทั้งหมด
- volume `redisdata` ไม่ถูกใช้แล้ว ลบทิ้งได้หลังอัปเดตด้วย `docker volume rm repolens_redisdata`
