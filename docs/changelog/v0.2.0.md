## เพิ่ม

- แพ็กเกจ `@repolens/analyzer` ที่ทำไปป์ไลน์หกขั้นครบ — ตรวจที่อยู่ โคลน สำรวจไฟล์ อ่านโครงสร้าง
  เชื่อมความสัมพันธ์ และสรุปผล พร้อมรายงานความคืบหน้าออกมาทุกขั้น
- อ่านโครงสร้างโค้ดด้วย tree-sitter (WebAssembly) สำหรับ TypeScript, TSX, JavaScript, Python, Go และ Rust
  และมีตัวแยกแบบรูปแบบข้อความเป็นตัวสำรองให้อีกกว่ายี่สิบภาษา
- เชื่อมความสัมพันธ์ระหว่างไฟล์ตามกติกาของแต่ละภาษา — เส้นทางสัมพัทธ์, ไฟล์ index, การนำเข้าแบบจุดของ Python,
  ชื่อโมดูลจาก `go.mod`, นามแฝง `@/` และ `#include` ของ C — พร้อมค่าความมั่นใจกำกับทุกเส้น
- ตัวโคลนที่ปิด symlink ของ git จำกัดเวลา และแปลงข้อความผิดพลาดของ git เป็นเหตุผลภาษาไทยที่ผู้ใช้อ่านรู้เรื่อง
- ตัวสำรวจไฟล์ที่ข้ามโฟลเดอร์ที่ถูกสร้างขึ้น แยกไฟล์ไบนารีออก และยังนับไฟล์ที่ใหญ่เกินอ่านไว้ในผลลัพธ์
- แพ็กเกจ `@repolens/db` — PostgreSQL 17 พร้อมระบบ migration ที่รันซ้ำได้และล็อกกันชนกันเอง
  เก็บผลวิเคราะห์ ไฟล์ เส้นเชื่อม และ symbol แยกตามคอมมิต
- แอป `@repolens/worker` ที่รับงานผ่านคิว BullMQ + Redis แยกกระบวนการจาก API
  เพื่อไม่ให้การโคลน repo ไปหน่วงหน้าเว็บ
- เส้นทาง API ใหม่: สั่งวิเคราะห์ ดูสถานะ ดูรายการไฟล์ ดูเส้นเชื่อม และติดตามความคืบหน้าแบบสตรีมด้วย SSE
- แคชผลตามคอมมิตและรุ่นของตัววิเคราะห์ — สั่ง repo เดิมซ้ำจะได้ผลเดิมกลับมาทันทีโดยไม่วิเคราะห์ใหม่
- จำกัดอัตราการสั่งวิเคราะห์ต่อหนึ่งที่อยู่ IP เพราะการโคลนกินทรัพยากรจริง
- หน้าเว็บใหม่: หน้าติดตามความคืบหน้าที่เดินตามขั้นตอนจริงผ่าน SSE และหน้าผลลัพธ์ที่สรุปจำนวนไฟล์
  บรรทัดโค้ด เส้นเชื่อม สัดส่วนภาษา ไฟล์ที่ถูกพึ่งพามากที่สุด และแพ็กเกจภายนอกที่ใช้บ่อย
- ชุดทดสอบปลายทางที่วิเคราะห์ repo ตัวอย่างจริงในเครือข่ายของ compose เอง จึงไม่ต้องพึ่งอินเทอร์เน็ต

## แก้

- `/api/health` ตอบ ok ทั้งที่ต่อฐานข้อมูลไม่ได้ — ตอนนี้ยิงคำสั่งเข้าฐานข้อมูลจริงก่อนตอบ
  compose จึงไม่ประกาศว่าบริการพร้อมทั้งที่ยังใช้งานไม่ได้
- โคลนโฟลเดอร์ที่เจ้าของไฟล์ไม่ตรงกับผู้รันไม่ได้ เพราะ git ปฏิเสธด้วยเหตุผลเรื่องความเป็นเจ้าของ
  ทั้งที่การโคลนเป็นการอ่านอย่างเดียวและเราไม่รันอะไรจาก repo เลย
- ที่อยู่ในเครื่องที่ไม่มีอยู่จริงให้ข้อความผิดพลาดดิบจากระบบไฟล์ — เปลี่ยนเป็น "ไม่พบโฟลเดอร์ที่ระบุ"

## หมายเหตุอัปเกรด

- รุ่นนี้เพิ่ม PostgreSQL 17 และ Redis 7 เข้ามาใน compose ทั้งสามชุด ต้องตั้ง `POSTGRES_PASSWORD` ใน `.env`
  ก่อนรันบนเซิร์ฟเวอร์จริง
- migration ถูกรันอัตโนมัติตอน API และ worker เริ่มทำงาน ไม่ต้องสั่งเอง
- เวอร์ชันของ web-tree-sitter ถูกตรึงไว้ที่ 0.20.8 ให้เข้าคู่กับไวยากรณ์ใน tree-sitter-wasms 0.1.13
  รุ่นใหม่กว่านั้นเปลี่ยนรูปแบบไฟล์ wasm จนโหลดไวยากรณ์ชุดนี้ไม่ได้
