## เพิ่ม

- คะแนนสุขภาพโค้ด A–F ที่เริ่มจากเต็มร้อยแล้วหักตามสิ่งที่วัดได้จริง
  ทุกข้อที่หักบอกได้ว่าหักเพราะอะไรและเท่าไร — ตัวเลขที่อธิบายที่มาไม่ได้ ใช้ตัดสินใจไม่ได้
- หาวงจรพึ่งพาด้วยอัลกอริทึมของ Tarjan เขียนแบบวนซ้ำ จึงไม่ล้นแม้กราฟจะลึกหลักหมื่น
- รัศมีผลกระทบรายไฟล์ — ถ้าแก้ไฟล์นี้ ไฟล์อื่นได้รับผลกี่ไฟล์ นับรวมผลทางอ้อมที่ไล่ต่อกันเป็นทอด ๆ
- หาโค้ดที่ไม่มีใครเรียกใช้ โดยยกเว้นจุดเริ่มโปรแกรม ไฟล์ทดสอบ ไฟล์ตั้งค่า และสคริปต์
- อ่านประวัติ git ย้อนหลังสองร้อยคอมมิต เพื่อบอกจุดร้อน (ไฟล์ที่แก้บ่อย ใหญ่ และมีคนพึ่งพาเยอะ)
  และบอกว่าควรถามใครเรื่องไฟล์นั้น
- สแกนความปลอดภัยเบื้องต้นเก้ากฎ — กุญแจที่เขียนตรงในโค้ด, กุญแจส่วนตัว, AWS key,
  การต่อสตริง SQL, eval, การส่งคำสั่งเข้า shell, การปิดตรวจใบรับรอง TLS, ตัวสุ่มที่ไม่เหมาะกับงานความปลอดภัย
  และคำสั่งดีบักที่ค้างอยู่ โดยยกเว้นไฟล์ทดสอบและเอกสารในกฎที่มักเจอค่าตัวอย่าง
- กลบค่าที่ดูเหมือนความลับก่อนเก็บลงฐานข้อมูลและก่อนแสดงบนหน้าเว็บทุกครั้ง
- โหมดลงสีที่สี่ของกราฟ — ตามรัศมีผลกระทบ
- แผงรายละเอียดไฟล์บอกรัศมีผลกระทบ จำนวนครั้งที่ถูกแก้ และผู้เขียนที่แตะไฟล์นี้บ่อยที่สุด
- หน้าสุขภาพโค้ดที่ `/a/[id]/report` — เกรด รายละเอียดการหักคะแนน จุดร้อน รัศมีผลกระทบสูงสุด
  ข้อสังเกตด้านความปลอดภัย วงจรพึ่งพา และไฟล์ที่ไม่มีใครเรียกใช้
- ส่งออกผลวิเคราะห์ทั้งชุดเป็น JSON ไฟล์เดียวที่ `GET /api/analyses/:id/export`
- เส้นทาง API ใหม่สำหรับข้อสังเกตด้านความปลอดภัยและการจัดอันดับไฟล์ตามมิติที่เลือก

## ปรับ

- โคลนลึกสองร้อยคอมมิตแทนคอมมิตเดียว เพราะจุดร้อนและเจ้าของโค้ดต้องใช้ประวัติ
- สแกนความปลอดภัยกับทุกไฟล์ที่อ่านเป็นข้อความได้ ไม่ใช่เฉพาะไฟล์โค้ด
  เพราะกุญแจที่หลุดบ่อยที่สุดอยู่ในไฟล์ตั้งค่าและไฟล์สภาพแวดล้อม
- เพิ่มขั้น "คำนวณตัวชี้วัด" เข้าไปในไทม์ไลน์ความคืบหน้า ให้ตรงกับสิ่งที่ระบบทำจริง
