# สถาปัตยกรรม RepoLens

เอกสารนี้อธิบายของที่ "มีอยู่จริงในโค้ดตอนนี้" ส่วนภาพรวมทั้งโครงการและสิ่งที่ยังไม่ได้ทำอยู่ใน [PLAN.md](../PLAN.md)

## สถานะปัจจุบัน: v0.2.0

อ่าน repo ได้จริงแล้ว — โคลน สำรวจไฟล์ อ่านโครงสร้างโค้ด และเชื่อมความสัมพันธ์ ส่วนกราฟแบบโต้ตอบเริ่มที่ v0.3.0

```
เบราว์เซอร์ ──▶ web (Next.js 15, พอร์ต 3000)
                 │  ส่งต่อ /api/* ──▶ api (Fastify 5, พอร์ต 3001)
                 │                       ├─ PostgreSQL 17  (ผลวิเคราะห์)
                 │                       ├─ Redis 7        (คิวงาน + ความคืบหน้า)
                 │                       └─ docs/changelog (บันทึกรุ่น)
                 │                              │
                 │                        คิว BullMQ
                 │                              ▼
                 └─ SSE ◀── ความคืบหน้า ── worker ──▶ git clone ──▶ tree-sitter ──▶ กราฟ
```

หน้าบ้านไม่คุยกับ API โดยตรงจากเบราว์เซอร์ แต่ผ่านตัวส่งต่อที่ `app/api/[...path]/route.ts`
ทำให้ทั้งตอนพัฒนาและตอนขึ้นจริงใช้เส้นทางเดียวกัน และ Caddy มีหน้าที่เดียวคือส่งทุกอย่างไปที่ web

ตัวส่งต่อเป็น route handler ไม่ใช่ `rewrites` ใน `next.config` เพราะ rewrites ถูกคำนวณตอน build
ค่า `API_ORIGIN` จะถูกฝังตายไปกับอิมเมจ (เจอปัญหานี้จริงตอนทดสอบ e2e ของ v0.1.0)
ส่วน route handler อ่านค่าตอนรันจริง และส่งต่อ body แบบสตรีมได้ ซึ่งจำเป็นกับ SSE ของไปป์ไลน์วิเคราะห์

## ทำไมแยก worker ออกจาก API

การโคลนและอ่านโค้ดกินเวลาหลายวินาทีถึงหลายนาที และกินหน่วยความจำเป็นก้อน
ถ้าทำในกระบวนการเดียวกับ API ทุกคำขอของผู้ใช้คนอื่นจะหน่วงตามไปด้วย
คิวยังทำให้ยกเลิก ลองใหม่ และจำกัดจำนวนงานพร้อมกันได้จากที่เดียว

## แพ็กเกจ

| แพ็กเกจ              | หน้าที่                                                                                             |
| -------------------- | --------------------------------------------------------------------------------------------------- |
| `@repolens/shared`   | สัญญาที่ใช้ร่วมกันทั้งระบบ — ชนิดข้อมูล, สคีมา Zod, ตารางระดับการใช้งาน, ตัวอ่านบันทึกรุ่น, ชื่อคิว |
| `@repolens/analyzer` | ไปป์ไลน์วิเคราะห์ทั้งหมด — ตรวจที่อยู่, โคลน, สำรวจไฟล์, tree-sitter, สร้างกราฟ                     |
| `@repolens/db`       | PostgreSQL — migration และการอ่านเขียนผลวิเคราะห์                                                   |
| `@repolens/api`      | Fastify — รับคำสั่ง ติดตามสถานะ และสตรีมความคืบหน้า                                                 |
| `@repolens/worker`   | ตัวรันงานจากคิว                                                                                     |
| `@repolens/web`      | Next.js — หน้าแรก หน้าความคืบหน้า หน้าผลลัพธ์ และหน้าประวัติเวอร์ชัน                                |

`@repolens/shared`, `@repolens/analyzer` และ `@repolens/db` คอมไพล์เป็น `dist/` ก่อนเสมอ
แล้วแอปที่เหลือค่อยใช้ผ่าน exports เพื่อให้ทั้ง Node และ Next เห็นของชิ้นเดียวกัน

## การอ่านโครงสร้างโค้ด

tree-sitter รุ่น WebAssembly เป็นตัวหลัก เลือกแบบนี้เพราะ binding แบบ native ต้องคอมไพล์ตอนติดตั้ง
ซึ่งทำให้อิมเมจใหญ่และพังง่ายเวลาเปลี่ยนเวอร์ชัน Node
เวอร์ชันของ runtime กับไวยากรณ์ต้องเข้าคู่กัน — `web-tree-sitter` 0.20.8 คู่กับ `tree-sitter-wasms` 0.1.13
ถ้าโหลดไวยากรณ์ไม่ได้ ตัวแยกแบบรูปแบบข้อความจะทำงานแทนและผลลัพธ์จะบอกว่าใช้ตัวไหนไป

## เส้นทาง API

| เส้นทาง                      | คืนอะไร                                                                  |
| ---------------------------- | ------------------------------------------------------------------------ |
| `GET /api/health`            | สถานะพร้อมใช้งานและเวลาที่รันมาแล้ว — ใช้กับ healthcheck ของ compose     |
| `GET /api/version`           | รุ่นที่กำลังรัน, git sha, เวลาที่ build, เลขสคีมาตัววิเคราะห์            |
| `GET /api/versions`          | บันทึกรุ่นทั้งหมด เรียงใหม่ไปเก่า                                        |
| `GET /api/versions/:version` | บันทึกรุ่นเดียว                                                          |
| `GET /api/session`           | ระดับการใช้งานปัจจุบันและรายการฟีเจอร์ที่ใช้ได้/ยังใช้ไม่ได้ พร้อมเหตุผล |

## ระดับการใช้งาน

นิยามอยู่ที่ `packages/shared/src/tiers.ts` ที่เดียว ทั้งหน้าบ้านและหลังบ้านอ่านจากตารางนั้น
รายละเอียดการตัดสินใจอยู่ใน [ADR 0001](decisions/0001-two-tier-byok.md)

## เลขรุ่นสองชุด

- **เวอร์ชันแอป** (`package.json` → `/api/version`) เปลี่ยนทุกครั้งที่ปล่อยของ
- **สคีมาตัววิเคราะห์** (`ANALYZER_SCHEMA` ใน shared) เปลี่ยนเมื่อผลวิเคราะห์รูปแบบเก่าใช้ไม่ได้แล้ว
  ซึ่งแปลว่าต้องล้างแคชผลวิเคราะห์ทั้งหมด — จึงแยกจากเวอร์ชันแอปโดยตั้งใจ
