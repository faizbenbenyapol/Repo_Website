# 0001 — สองระดับการใช้งาน และ AI แบบใส่ API key ของตัวเอง (BYOK)

- สถานะ: ตกลงแล้ว
- วันที่: 2026-09-07
- เกี่ยวข้องกับ: `packages/shared/src/tiers.ts`, `GET /api/session`

## บริบท

เป้าหมายของโปรเจกต์คือ "ใส่ลิงก์ repo แล้วเข้าใจได้ทั้งหมด" ซึ่งต้องมีชั้น AI มาสรุปและตอบคำถาม
แต่ชั้นนี้มีค่าใช้จ่ายต่อการเรียกใช้จริง ถ้าเปิดให้ทุกคนใช้ฟรีโดยเจ้าของเว็บออกค่าโมเดลเอง
ค่าใช้จ่ายจะโตตามจำนวนผู้ใช้แบบที่คุมไม่ได้ และต้องทำระบบโควต้าซับซ้อนตั้งแต่วันแรก

## การตัดสินใจ

แบ่งการใช้งานเป็นสองระดับ

| ระดับ                                        | ได้อะไร                                                                                                                                                                           | ใครออกค่าโมเดล |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| **ผู้เยี่ยมชม** (ไม่ล็อกอิน)                 | ผลวิเคราะห์เชิงโครงสร้างทั้งหมด — กราฟความสัมพันธ์ ต้นไม้ไฟล์ ตัวชี้วัดสุขภาพ รัศมีผลกระทบ จุดร้อน เจ้าของโค้ด สแกนความปลอดภัย ส่งออก JSON — เทียบเท่ากับที่ CodeFlow ต้นทางทำได้ | ไม่มี          |
| **สมาชิก** (ล็อกอิน + ใส่ API key ของตัวเอง) | ทุกอย่างข้างบน บวกชั้นความเข้าใจ — สรุป repo ภาษาไทย สรุปรายไฟล์ ถาม–ตอบพร้อมอ้างอิง เส้นทางอ่านโค้ด อภิธานศัพท์ รายงานภาษาไทย                                                    | ผู้ใช้เอง      |

## ผลที่ตามมา

- ฟีเจอร์ทุกตัวต้องประกาศไว้ที่เดียวว่าอยู่ระดับไหน (`FEATURES` ใน `@repolens/shared`)
  แล้วทั้งหน้าบ้านและหลังบ้านอ่านจากตารางเดียวกัน จะได้ไม่มีกรณีที่ปุ่มกดได้แต่ API ปฏิเสธ
- API key ของสมาชิกถือเป็นความลับระดับสูงสุดของระบบ: เก็บใน session ฝั่งเซิร์ฟเวอร์แบบเข้ารหัส
  มีวันหมดอายุ ไม่ลงดิสก์ ไม่ลง log ไม่ส่งกลับไปหน้าบ้าน และแสดงได้แค่สี่ตัวท้าย
- ผลวิเคราะห์เชิงโครงสร้างแคชร่วมกันได้ทุกคน แต่ผลจาก AI ผูกกับผู้ใช้ที่จ่ายค่าโมเดล
- ทุกหน้าจอที่มีฟีเจอร์ระดับสมาชิกต้องบอกให้ชัดว่าทำไมยังใช้ไม่ได้ และต้องทำอะไรถึงใช้ได้
  ไม่ใช่ปุ่มจาง ๆ ที่กดไม่ได้โดยไม่บอกเหตุผล
- ระบบล็อกอินและช่องใส่ API key จะลงจริงในรุ่น v0.5.0 พร้อมกับชั้นความเข้าใจ
  รุ่นนี้ (v0.1.0) วางแค่ตารางระดับการใช้งานและ `GET /api/session` ที่รายงานสถานะปัจจุบัน

## ทางเลือกที่ไม่เลือก

- **เจ้าของเว็บออกค่าโมเดลให้ทุกคน** — ค่าใช้จ่ายโตตามผู้ใช้ ต้องมีโควต้าและระบบกันใช้เกินตั้งแต่วันแรก
- **ปิดทั้งเว็บให้เฉพาะสมาชิก** — เสียคุณค่าข้อที่ดีที่สุดของต้นทาง คือเปิดมาก็ใช้ได้เลย
- **ให้ใส่ API key โดยไม่ต้องล็อกอิน** — ไม่มีที่ผูกกุญแจกับตัวตน จำกัดการใช้ผิดวิธีไม่ได้ และกู้คืนสถานะให้ผู้ใช้ไม่ได้
